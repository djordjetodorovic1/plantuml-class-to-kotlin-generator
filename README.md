## 📖 About the Project
Developing software systems involves automating various activities, including the translation of textual models into functional code, which reduces the possibility of errors and accelerates development. This project is an implementation of a translator that automatically transforms input PlantUML models into Kotlin object-oriented programming code. 

The translation process goes through four key phases:
* **Lexical analysis**
* **Syntax analysis**
* **Semantic analysis**
* **Code generation**

---

## 🛠️ Technologies Used
* **Python**: The main programming language used to implement the tree logic, semantic analysis, and the code generator.
* **ANTLR4**: A parser generator tool used to define the grammar and generate the lexical analyzer and syntax parser.

---

## ⚙️ System Architecture

### 1. Lexical and Syntax Analysis
* The lexical analyzer and syntax parser were created using the **ANTLR4** tool based on a specifically defined grammar.
* Lexical rules recognize basic tokens: keywords, identifiers, visibility modifiers, relations, brackets, and numbers, while comments and whitespaces are ignored.
* Syntax rules create a hierarchy of elements, where definitions (classes, interfaces) are further parsed as lists of their respective attributes and methods.

### 2. Abstract Syntax Tree (AST) Construction
* After parsing, an abstract syntax tree (AST) tailored to the problem domain is built using **Python** classes.
* The tree is built using the `ASTBuilder` class, which inherits the *Visitor* class and traverses the tree generated by the parser, extracting only semantically important data.
* The tree structure consists of specialized nodes: `DiagramNode`, `ClassNode`, `AttributeNode`, `MethodNode`, `ParamNode`, `EnumNode`, and `RelationNode`.

### 3. Semantic Analysis
Before code generation, rigorous checks are performed to ensure the model's validity:
* Checking for duplicate class, attribute, and method names.
* Checking for the existence of cycles during inheritance.
* Mandatory implementation of all interface methods by the classes that implement them.
* Detection of non-existent referenced elements and validation of source and target compatibility in relations.

### 4. Code Generation
The final phase involves traversing the validated AST to dynamically produce idiomatic **Kotlin** source code. The code generator handles several specific Kotlin language features:

* **Classes and Primary Constructors:** The generator maps PlantUML classes to Kotlin `class` definitions. It intelligently constructs Kotlin's primary constructors by analyzing class attributes and necessary superclass arguments.
* **Inheritance and Interfaces:** PlantUML inheritance (`<|--`) and realization (`<|..`) are translated using Kotlin's `:` syntax. The system automatically enforces the `override` keyword for methods derived from abstract classes or interfaces.
* **Properties and Visibility:** PlantUML visibility modifiers (`+`, `-`, `#`, `~`) are translated into their Kotlin equivalents (`public`, `private`, `protected`, `internal`). Attributes are declared as properties (`var` or `val`), with basic type inference or direct mapping to Kotlin standard types (e.g., `String`, `Int`).
* **Relationships to Collections:** The generator analyzes relation multiplicities (e.g., `1..*`, `0..*`). One-to-many or many-to-many relationships are automatically translated into Kotlin collection types like `List<T>` or `MutableList<T>`, while one-to-one relationships are generated as standard object references.
* **Enumerations:** PlantUML `enum` blocks are directly translated into Kotlin `enum class` constructs, preserving all named constants.
* **Method Stubs and Compilation:** Method signatures are generated with their appropriate return types and parameters. To ensure the output code is immediately compilable, method bodies are generated with Kotlin's built-in `TODO("Not yet implemented")` function.
